## 2026-11-25 新首领「雪人王」：霜渊第 10 波压轴，往炮塔丢雪球压攻速

**需求**：给霜渊做一只专属压轴首领。它不砸塔、不脉冲熄火，而是**朝炮塔丢雪球**，
被砸中的塔攻速下降一段时间（塔不会被摧毁）。是否启用由地图字段控制，没配置的图继续用通用「大首领」。
**追加需求**：雪人王要改成真 3D 模型，并且造型要改造，不能和原画太像。

**改动**

- `scripts/SnowkingModel.gd`（新增）：雪人王的**程序化 3D 造型**，敌人与图鉴共用。
  三层压扁雪球（头球单独抬高一截）+ 冰晶腰带 + 发光冰蓝眼与斜眉 + 短粗胡萝卜鼻 +
  五棱冰晶王冠 + 横躺的六棱冰甲肩片 + 胸口双锥冰核 + 三道背部冰刺 +
  不对称树枝手（右手托着一颗蓄力雪球）。
  和原画的差异就是「改造」本身：原画是光膀子三球雪人，这里加了王冠 / 冰甲 / 冰核 / 背刺 / 装备感。
  雪体压到 `(0.85, 0.90, 1.0)`，不是纯白 —— 霜渊的雪地本来就接近纯白。
- `textures/enemy_snowking.png`：原画保留在工程里只作设计参考，**游戏内不再使用**
  （处理脚本 `tools/gen_snowking_sprite.py`、原图 `tools/art/snowking_src.png` 照旧保留）。
- `data/EnemyData.gd`：`Kind.SNOWKING`「雪人王」，1700 血 / 0.95 速 / 240 金 / 体型 2.90 / 护甲 0.15；
  新增 `SNOWBALL_*` 常量组（间隔 6s、射程 8.5、减速 35%、持续 5s、半血后间隔 ×0.6、飞行速度 9、抛物线高度 1.3、召唤 2 只霜崽）。
- `scripts/Enemy.gd`：`Kind` 枚举补 `SNOWKING`；`is_boss()` 把它算作首领；
  `_tick_boss_skill()` 走雪球分支（`_first_skill_delay()` / `snowball_interval()`）；
  `_throw_snowball()` 挑**射程内等级最高**的塔（同级取最近），射程内没塔就只抬手、1 秒后重试，不浪费 6 秒冷却；
  半血「暴雪」缩短雪球间隔并召唤 2 只霜崽；外观走 `_build_snowking_body()`（SnowkingModel，真 3D），
  血条按实测 `_body_h` 抬高、冰蓝光环 + 「BOSS」标记；半血染色改成冰蓝（不是大首领那种狂暴红）。
- `scripts/Snowball.gd`（新增）：抛物线飞行（水平 lerp + sin 拱），命中调 `tower.chill()`；
  目标塔在飞行途中被卖掉只放雪雾不结算；`GameState.running` 为 false 时停在空中（暂停 / 波间不砸塔）。
- `scripts/Tower.gd`：新增 `atk_slow` / `_atk_slow_timer`；`shot_interval()` 把 `(1 - atk_slow)` 乘在面板攻速上
  （不改 `fire_rate`，debuff 到点自动恢复，也不污染升级 / 变异数值）；`chill()` 取更强 + 刷新时间、不叠乘；
  脚下冰蓝提示圈、首次命中飘字、浮窗与面板显示「被雪球砸中 / 当前实际攻速（原 X）」。
- `scripts/Waves.gd`：`big_boss_kind(opts)` 读 `opts["big_boss"]`（默认 `Enemy.Kind.BOSS`），
  第 10 波与无尽每 10 波用它替换压轴首领；`boss_name()` 跟着变，预告按钮能显示「雪人王」。
- `scripts/Main.gd`：`_wave_opts()` 按地图 `snowking` 字段写入 `opts["big_boss"] = Enemy.Kind.SNOWKING`。
- `scripts/MapDefs.gd`：字段说明补 `snowking`，霜渊图开启。
- `scripts/TextureLib.gd`：`enemy_snowking` 从 billboard 原画精灵白名单移除（只剩霜崽）。
- `scripts/GameUI.gd`：图鉴加雪人王（`_codex_suffix` 返回 "snowking"）；
  没有 GLB 时**直接构建同一套 3D 造型**预览，而不是贴一张立绘。

**验证**（`--headless` 扫描 + 导入，另跑临时脚本查波次 / 数据 / 模型）

- 工程扫描与 `--import` 无 SCRIPT ERROR / Parse Error。
- `SnowkingModel.build(2.9)`：29 个 MeshInstance3D，实测高 4.05（`ModelLib.height_of`）、
  包围盒宽 4.27（含张开的手臂），`meta("body_mat")` 能取到主雪体材质（染色用）。
- 实机：临时场景把 `MapDefs.pending_id` 设为 "frost" 加载主场景，`debug_spawn_at(SNOWKING, ...)`
  刷出 1 只并把相机拉近截图 —— 模型站在雪径上约 2 格高，血条在头顶上方、`BOSS` 标记在血条上方，没有重叠；
  正面 / 背面都能看到王冠、肩甲、腰带、背刺与托着的雪球。
- `Waves.plan(10, {"big_boss": SNOWKING})` 末尾是 `[TANK, TANK, MINI_BOSS, SNOWKING]`，`has_snowking = true`；
  `boss_name(10, {})` = 「大首领」，带 opts = 「雪人王」—— 默认图不受影响。
- `Enemy.DATA[SNOWKING]` 取到 hp 1700 / snowball true。

**踩的坑**

- `EnemyData.Kind` 和 `Enemy.Kind` 是**两份独立枚举**，只加一份会报
  `Cannot find member "SNOWKING" in base "Enemy.Kind"`（EnemyData 是数据表的 key，Enemy 是运行时类型）。
  两份顺序必须完全一致。
- 首领用 billboard 立绘会穿帮：本作是能绕视角的 3D 场景，方片一转就露馅，所以雪人王必须真 3D；
  立绘方案只留给霜崽这种小杂兵。
- 程序化模型最容易犯的错是**五官被球面吞掉**：第一版眼睛中心放在 z=0.18s、头球半径 0.22s，
  整颗眼球埋进雪里，渲染出来就是「没有眼睛」。眼睛 / 嘴 / 冰核的 z 必须顶到该高度球面**外面**
  （头半径 0.25s → 眼睛中心 0.235s），必要时宁可让眼球一半露在球外。
- 肩甲不能做成「立着的高锥」：从正面会把中球两侧包住，看起来像两只蓝爪子捂脸；
  改成**横躺的薄圆盘**扣在肩头（`rotation.z ≈ ±1.0`、高度 0.075s）才像护肩。
- 雪体不要纯白：霜渊地面本身就是纯白，纯白雪人只剩一团过曝白斑；压到 `(0.85, 0.90, 1.0)` 才有体积感。
- 验证造型要看**真实玩家相机**：正交/平视近景看不出俯视时王冠会不会被头球挡住，
  临时场景里把 `cam_height` 调到 16 截一张，才看出王冠要加宽加高、背刺要斜向后上方。
- 首领模型比程序化方块高（雪人王 4.05 vs 大首领 3.34），`_build_bar()` 用 `_body_h` 抬高血条后，
  仍按 `1.05*s+0.25` 算位置的 `_build_boss_marker()` 会被血条压住 —— 标记高度改成读 `_bar_root.position.y + 0.60`。
- `_body_h` 必须用 `ModelLib.height_of()` 实测：雪球是用 `SphereMesh.height` 压扁的椭球，
  不是半径 ×2，手写常数会让血条和雪球出手点都偏。
- 新精灵光有 png 不够：`TextureLib` 里有一份 billboard 原画槽位白名单，不加进去 `_build_sprite_body()` 直接返回 false，
  会静默回退成方块（雪人王改 3D 后这条只对霜崽有效）。
- `for t in get_tree().get_nodes_in_group("towers")` 拿到的 `t` 是 Variant，
  `var d := t.global_position.distance_to(...)` 会触发 `Cannot infer the type of "d"` —— 显式写 `var d: float = ...`。
- `godot --headless -s script.gd` 跑独立脚本时**不会加载 autoload**，碰到 `Sound` 就报 `Identifier not found: Sound`，
  所以这类验证脚本只用 `Waves` / `EnemyData` / `TextureLib` 这些纯静态类，别实例化 `Enemy`。

## 2026-11-25 新怪「霜崽」+ 雪地图的布防台改成白雪台

**需求**：给了一张冰晶小怪的原画，要它当一只小杂兵；**冰面被凿开以后它也能从水下走**；
另外霜渊的布防台（原来的灰石台 + 木板）要改成更符合雪地的白色雪台。

**改动**

- `textures/enemy_frostling.png`（新增）：原画抠掉棋盘格背景后的透明精灵（128×128）。
  处理脚本 `tools/gen_frostling_sprite.py`，原图存 `tools/art/frostling_src.png`，重跑一次就能再生成。
- `scripts/Enemy.gd`：`_build_sprite_body()` 把精灵贴在**永远正对镜头的方片**上（1 个 draw call）。
  新增 `underwater` 标记：能走水下段，但**自己不砸冰** —— `_start_swim()` 里提前 return，
  只留一个小水花 + 波纹 / 暗影，冰洞和碎冰特效仍然只有碎冰者才有。
- `data/EnemyData.gd`：`Kind.FROSTLING`「霜崽」，52 血 / 2.9 速 / 11 金 / 体型 1.05 / `underwater: true`。
- `scripts/Waves.gd`：冰原图第 2 波起混入霜崽，每波 2~8 只（比碎冰者早一波，数量也多）。
- `scripts/Main.gd`：`_wave_opts()` 跟着 `icebreaker` 一起开霜崽；两个刷怪入口（正式波次 / 上帝模式）
  **都**按 `GameState.ice_opened` 决定走雪径还是水下段 —— 霜崽自己不碎冰，冰面没通时它就走大路，
  测试时看到的和玩家看到的完全一致。
- `scripts/GameState.gd`：新增 `ice_opened` —— 碎冰者第一次下水时置 true，`reset()` 里清掉
  （换图 / 重开都会走 reset，所以天然是「一局一张图」）。
- `scripts/GameGrid.gd`：`_build_snow_slots()` —— `ground = "snow"` 的图改用**白色雪圆台 + 接地淡影 + 青色台脚光边**；
  草地地图保持原来的石台 + 木板不变。
- `scripts/GameUI.gd` / `scripts/MapDefs.gd`：图鉴加霜崽（没有 GLB 时用贴图精灵预览）；
  提示文案从「蓝色布防台」改成「发光的布防台」，霜渊的地图说明补一条霜崽。

**为什么**

- 碎冰者凿穿冰面那一刻应该被玩家**看见并利用**：霜崽跟着冰洞游过去，等于告诉玩家
  「湖通了以后，冰面这一侧也不再安全」，同时让冰原的杂兵有自己的辨识度（而不是又一个小兵换皮）。
- 石台 + 木板在整张白蓝的霜渊里是唯一的灰 / 暖褐色块，像贴了别人的素材；
  雪台只靠明度差和青边区分，画面才是一整片雪原。

**验证**（实机跑 frost 图，日志 + 截图）

- 冰面没通：上帝模式刷一只、正式波次连刷 3 只，`swim_from` 全是 `-1`（走大路绕湖）。
- 碎冰者下水后：`ice_opened = true`；再刷的霜崽 `swim_from` 分别为 9 / 7 / 7，
  `_swimming = true`、`bodyY ≈ -1.23`（冰面在 0.85），整只沉到冰下，只有波纹圈露在冰面上。
- 布防台：雪地图是白色雪台，塔建上去台面顶 ≈ 0.866 和石台版齐平，塔底照样陷进去一点。

**踩的坑**

- 原画是一张「棋盘格烘焙进像素」的截图：要从四边泛洪、只吃暗色像素（max 通道 < 90）抠背景，
  并且**只保留面积最大的连通块** —— 原图顶上还露着另一个素材的半截，不筛掉会一起导出。
- 缩放必须**预乘 alpha**（`convert("RGBa")`）：直接 resize 会把透明区的白色混进边缘，
  游戏里小怪周围会多出一圈白雾。
- 精灵材质千万别用 `TRANSPARENCY_ALPHA`：半透明会被排进透明队列、不写深度，
  于是「沉到冰面下」的身体又会从冰面里透出来 —— 用 `ALPHA_SCISSOR`（阈值 0.45）。
- 雪台别用纯白：霜渊环境光亮，纯白会直接过曝成一个没有体积感的圆片，压到 `(0.80, 0.88, 0.98)` 刚好；
  另外要靠最外圈一道淡投影把它「抬」起来，否则像贴在雪面上的贴纸。

## 2026-11-25 碎冰者模型配色改成「冰蓝水晶巨魔」

**需求**：碎冰者的 GLB 要按「冰蓝水晶巨魔」出（原来皮肤是青绿色，偏孔雀石，不像冰）。

**改动**

- `tools/gen_enemy_models.py`：`FROST_SKIN` 从灰绿 `(0.30,0.53,0.47)` → 幽蓝 `(0.21,0.37,0.56)`；
  `data/EnemyData.gd` 里 ICEBREAKER 的 `color` 同步（它管程序化兜底身体和图鉴色块，
  两边不一致的话没放模型时会变回旧颜色）。
- 造型不动：驼背宽肩 + 冰晶前臂（octa 双锥）+ 头顶水晶冠 + 后掠双角 + 黄眼 + 背棘，
  540 三角面 / 12 材质，`y0=0.00 h=1.42 x=[-0.81,0.81]`。
- 重新生成 + 清 `.godot/imported/enemy_icebreaker*` + `--import`，四视图与霜渊实机各看了一遍。

**为什么是这个蓝**：霜渊图整张是白 / 浅蓝的雪地 + 冻岩，冻岩本身就是 `(0.30,0.42,0.60)`。
冰蓝要「比冻岩更暗更蓝」才既像冰又不会糊进背景里 —— 亮蓝会和雪地、灰蓝会和岩壁混成一片。

**踩的坑**：`gen_enemy_models.py` 是确定性的（同样的参数 → 同样的字节），所以只改配色时
**必须确认 GLB 真的变了**（mtime / md5），否则 `--import` 直接跳过，看到的还是旧模型。

## 2026-11-25 修：碎冰者不走路，横穿草坪直奔基地

**现象**：碎冰者（`Kind.ICEBREAKER`）完全无视雪径，从草地里斜着直线走向基地，也不下水。

**原因**

- `GameGrid._swim_passable()` 原来写的是「陆地只要没装饰就算可走」。A* 的代价是
  水面 0.85、破冰小径 0.5、普通格 1.0，于是**在草坪上抄直线永远比沿弯曲的雪径便宜** ——
  「会游泳」被实现成了「全地形可走」。
- 实测（frost 图）：从 `(20,3)` 出发，20 格路线里 17 格在草坪、**0 格水面**（连游泳都没触发）；
  从入口 `(8,0)` 出发也有 11 格离路。

**改动**

- `_swim_passable()`：陆地只允许 `路线格 / 破冰小径 / 基地格`，水面照旧一律可走。
  它该给人的印象是「沿雪径走，只在湖面那一段砸冰抄近道」。
- `swim_route_home(from)`：起点不在可走格上时（上帝模式会点在空地上）先用
  `_nearest_swim_cell()` 吸附 —— **优先吸附到路面**，附近实在没路才落水 ——
  再把原格补在路线最前面（lead），水面段下标整体后移。
- `Main.debug_spawn_at()`：只有 `grid.has_water()` 且这条线确实经过水时才用游泳路线，
  没水的图直接沿雪径走（否则会为一只「会游泳的怪」算出横穿草坪的直线）。

**结果**：入口 `(8,0)` 的 35 格 = **0 格离路 + 15 格水面**；`(0,10)` 同理；
空地 `(20,3)` 只有起点那 1 格需要先走上路面，其余全在路 / 水上。

**踩的坑**

- 「它能抄近路」应该是**水面特权**，不是全地形特权：A* 里放行空地等于给了一只穿墙怪。
- 吸附起点要优先路面，否则点在山坡上会看到它斜着走进湖里，像凭空入水。
- 补了 lead 格之后，`swim` 的 `(from,to)` 下标必须跟着 `+lead.size()` 偏移，
  否则它会在岸上就开始「游泳」（身体下沉 + 水花特效）。

## 2026-11-25 上帝模式：任意格子刷怪（测试用）

**需求**：不想每次都跳波 / 等出怪口，想随时随地（地图上任何位置，包括水面、岩石、路线外）
手动放怪来测某座塔的强度。

**改动**

- `Main.debug_spawn_at(kind, cell, count, hp_mult)`：在**任意格**生成敌人。不需要路线格 ——
  `grid.path_home_cells_from()` 对非路线格会挑「离它最近的那一格路线」，从那里顺着 lane 回家；
  碎冰者单独走 `swim_route_home()`，否则它会被当成普通怪沿雪径走。
  血量 = `Waves.hp_scale(当前波) × 面板倍率`；多只时在格子里摊成一小圈，不然会完全重叠。
- `GameUI`：右上角新增「上帝模式 F2」（槽位 6）+ **顶部正中**的一块小面板：
  怪物类型（遍历 `Enemy.DATA.keys()`，以后加新怪不用改这里）/ 一次 1·3·5·10 只 / 血量 ×1·×3·×10 / 关闭。
- `Main._on_left_press()`：面板开着时，左键**先于**建造 / 选中处理，直接在该格刷怪并 `return`
  —— 不进入平移拖动，平移继续交给中键。ESC 也能关面板。

**踩的坑**

- 「面板开着 = 左键放怪」比「开个开关再记着自己已开启」可靠：不需要额外的 armed 状态，
  **面板本身就是提示**，不会出现「忘了关，结果怎么点都在放怪」。
- 面板不能放右上角按钮列下方：那列到「地图切换」（槽位 5，底边 618）已经顶到底，
  再往下放不下面板。顶部正中（左右两侧的信息栏之间）是唯一空着的地方。
- 面板宽度是固定像素，里面的提示 Label 必须 `autowrap_mode = WORD_SMART`，
  否则整行中文直接溢出到地图上。
- 自测时注意：`_on_left_press()` 读的是 `get_viewport().get_mouse_position()`（不是事件里的位置），
  所以 `viewport.push_input()` 造出来的点击**不会**改变它 —— 要么先 `Input.warp_mouse()`，
  要么改成断言「有没有刷出怪 / 有没有进入平移」这类与坐标无关的量。

## 2026-11-23 毒瓶塔模型重做：绿汤要看得见，炼金师要站得出来

**需求**：毒瓶塔（大铁锅 + 绿汤 + 猫耳炼金师 + 举瓶子的手臂）在实机俯视角下"只剩一个灰盖子"，

## 2026-11-18（深夜）变异「霜环」改成不攻击的冰雾光环塔

**动机**：霜环原来的定位是「减速 +14%，溅射范围 +1.0」，本质还是「冰塔加强版」——
和另外两条路线（碎冰打伤害、寒潮打射程）在同一条赛道上比数值。
改成一个**纯辅助光环**：放弃全部输出，把射程圈铺满冰雾，圈内敌人恒定减速 50%。
这样玩家要做的是「把路卡进雾里」而不是「再多一座 DPS 塔」，选择才有取向差异。

**改动**

| 位置 | 内容 |
| --- | --- |
| `scripts/FrostFog.gd`（新增） | 冰雾表现层：三层同心圆盘（主雾体 / 细节 / 高光丝）平铺在地面上，反向缓慢自转 + 呼吸；形状用**网格顶点 alpha**（`vertex_color_use_as_albedo`）烘成「中心浓、边缘淡」，贴图 UV 缩放到铺满整圈 |
| `textures/fx_frost_fog.png`（新增） | 冰雾贴图：从参考图裁出、抠掉棋盘格背景（亮度取 alpha + 反预乘），按 alpha 重心裁成 256×256 正方形、雾团居中、四周透明 |
| `data/TowerData.gd` | 霜环：`mods` 改为 `{"dmg_mul": 0.0, "slow_set": 0.50}` + 顶层 `"aura": true`；`desc` 重写。`slow_set` 是新增的 mods 字段（把减速定死，不叠基础塔的 0.22） |
| `scripts/Tower.gd` | 新增 `is_aura()` / `_update_aura()` / `_rebuild_fog()`：`_process` 里光环塔走最前面那条分支（既不射线也不打子弹）；每次重建塔身按当前 `range_v` 重铺冰雾；被压制时雾熄灭；`info_text()` 对光环塔显示「射程内减速 50% · 不造成伤害」 |
| `scripts/TextureLib.gd` | 槽位表加入 `fx_frost_fog` |
| `README.md` | 变异章节补「霜环 = 光环塔」，`mods` 字段表补 `slow_set` / `aura` |

**设计要点**

- **真的没有伤害**：`dmg_mul: 0.0` 让 `damage` 归零，且 `_update_aura()` 只调 `apply_slow()`，
  不碰 `take_damage()`，也不走 `Bullet.apply_on_hit_status()`（毒 / 流血 / 破甲属于「弹药词条」，
  不打伤害的塔不该触发）。射线节点会被 `_beam.stop()` 彻底关掉，不会留一条残线。
- **为什么雾是圆盘 + 顶点 alpha**：一张方片贴图铺开会把四个角捅到射程圈外；要在
  `StandardMaterial3D` 里做径向遮罩只能上自定义 shader。这里把同心环的 alpha 直接烘进网格
  （1.0 → 0.88 → 0.42 → 0），配合 UV 缩放把贴图拉到满圈，就得到「整圈是雾、边缘自然淡出」，
  既不写出圈也不出现硬切边，还省了一个 shader。
- **半径跟着射程走**：雾节点整体 `scale = range_v`，并在 `_build_body()` 里重建，
  所以升级、寒潮（射程 +25%）、卡牌射程加成之后雾圈和射程圈仍然严丝合缝。
- **压制联动**：被大首领脉冲压制时冰雾 `visible = false`，玩家能直接看出这座塔暂时失效。
- **成本**：每座霜环塔常驻 3 个 MeshInstance3D + 1 份共享网格，减速每 0.2 秒刷一次，
  比让它每 0.95 秒生成一颗子弹更省。

**怎么自测**

1. 冰塔升到 Lv.3 → 选「霜环」：塔身停止射击，射程圈内立刻铺满淡蓝冰雾（雾会缓慢翻涌）。
2. 敌人走进雾圈：立刻进入减速状态（身上变蓝、移动明显变慢），并且**不掉血**、不出现伤害数字。
3. 给塔喂射程（寒潮 / 射程卡）后升级：雾圈和射程圈应同步变大，不会出现「雾比圈小」。
4. 卖塔 / 重开：雾节点随塔一起销毁，不留残影。

## 2026-11-18（晚）冰塔改为「持续冰冻射线」

**动机**：冰塔原来是「射一发冰弹 → 命中一次 → 结算一次伤害」，和箭塔 / 炮塔是同一套手感，
只在附带减速上有所区别。参考 Kingdom Rush 里工程师 / 冰系塔的攻击表现（那道扭动的青白能量束，
末端在敌人身上炸开），把冰塔改成**锁定敌人一直照射**的射线塔：冻住谁、冻了多久，一眼就看得到。

**改动**

| 位置 | 内容 |
| --- | --- |
| `scripts/IceBeam.gd`（新增） | 射线表现层：`ImmediateMesh` 画两条正对镜头的三角带（外圈青蓝光晕 + 内圈近白核心，ADD 叠加），路径上叠正弦扰动；命中点 / 塔口各挂一团程序化径向光斑（`GradientTexture2D` 径向渐变，无需外部贴图）。起手 0.15 秒渐亮，不闪 |
| `scripts/Tower.gd` | 新增 `is_beam()` / `shot_interval()` / `_update_beam()` / `_beam_apply()` / `_in_range()` / `_sync_beam_look()`；`_process` 里射线塔走独立分支（不生成 `Bullet`，`_beam_tick` 等价于原来的 `cooldown`），暂停 / 被首领压制时自动断线；`_build_base()` 挂 `IceBeam`，`_build_body()` 按等级 / 变异同步粗细与颜色 |
| `scripts/Bullet.gd` | 把「减速 + 毒 / 流血 / 破甲 / 易伤」抽成 `static apply_on_hit_status()`，子弹和射线共用一份实现 |
| `scripts/Fx.gd` | `burst_seq()` 增加可选 `tint` 参数：炮塔爆炸仍是暖橙，碎冰走冷蓝，不会被自发光染成橙色 |
| `textures/fx_ice_0.png` / `fx_ice_1.png`（新增） | 射线命中时的碎冰序列帧：从参考图 `go_towers_engineer_kr1-1.png` 裁出两组，抠掉棋盘格背景（按亮度取 alpha + 反预乘），58×40 带透明通道，共 2 帧 |
| `scripts/Tower.gd` `_beam_apply()` | 每次结算伤害时在主目标身上放一团碎冰（`Fx.burst_seq("fx_ice", …)`）；没放贴图就回退成冰蓝闪光 + 冲击环 |
| `scripts/TextureLib.gd` | 槽位表加入 `fx_ice_0` / `fx_ice_1`，开局「还缺哪些图」的报告里能看到 |
| `data/TowerData.gd` | 冰塔加 `"beam": true`，`desc` 改写（伤害与射速的数值一个都没动） |
| `README.md` | 塔数值基线、减速说明补上「冰塔是射线塔」的口径 |

**设计要点**

- **只换表现，不换数值**：伤害节奏还是原来的「每 `1/攻速` 打一发满额 `damage`」。
  最初试过摊成「每秒伤害 = `dmg × rate`」的连续掉血，但手感和面板都对不上（射速这一栏会失去意义），
  所以最终保留原攻速与原单发伤害，只是**省掉了子弹飞行的那 0.3 秒**：锁上就打，射线一直连着。
- **`_beam_tick` 就是 `cooldown`**：累加到 `shot_interval()` 就打出一发，然后用减法扣掉间隔
  （不是清零），掉帧时长期射速不会漂。
- **溅射 / 暴击 / 附带状态全走原规则**：主目标吃满、圈内其他敌人吃 `SPLASH_DMG_COEF` 衰减；
  暴击每次独立 roll；减速与毒 / 流血 / 破甲 / 易伤由 `Bullet.apply_on_hit_status()` 统一处理。
- **换目标**：目标死亡（含 `hp <= 0`）/ 走出射程 / 隐身时自动重挑（口径与 `_find_target` 相同，
  所以「目标优先级 Q」对射线塔同样有效），重挑节流仍是 `AIM_REFRESH`。
- **命中特效只在主目标身上**：溅射圈里的其他人不额外放碎冰，否则一次开火能同时炸出 5 团冰花，
  比伤害数字还乱。特效时长 0.3 秒、按 `1/攻速`（约 0.95 秒）的节奏重复，看起来就是「射线一直
  在敌人身上结霜」。
- **参考图是棋盘格预览图**：直接当贴图用会把深灰格子也带进来，所以先按亮度取 alpha，再用
  反预乘把背景色从半透明边缘里减掉（否则边缘会带一圈灰边）。
- **不新增节点**：射线是一个 `ImmediateMesh` + 两个 billboard 光斑，每帧重画顶点；
  每座冰塔常驻 3 个节点，比「每次开火生成一颗子弹」更省。

**怎么自测**

1. 第 3 波后建一座冰塔，敌人进入射程：塔顶冰晶到敌人之间会出现一条扭动的青白射线，
   命中点有一团脉动的冰爆光斑；伤害数字与掉血节奏应和改造前一致（Lv.1 约每 0.95 秒跳一次 9）。
2. 每次结算伤害时，主目标身上会炸开一小团碎冰（`fx_ice` 两帧，0.3 秒淡出），
   和射线一起看就是「冰束在敌人身上不断结霜」。
3. 敌人走出射程 / 被打死：射线立刻断开并自动挂到下一个目标。
4. 敌人身上应持续保持冰蓝色（每次命中都在刷新减速）；喷火塔打它时仍然吃「冰火两重天」加成。
5. 满级选变异：射线的光晕颜色会变成变异色（霜环淡蓝 / 碎冰亮白 / 寒潮深蓝），Lv.3 也更粗。

## 2026-11-18 炮塔特效分级 · 攻城巨炮序列帧 · 震地雷泥潭

### 1. 炮塔命中特效按等级分级

**动机**：一级炮塔的爆炸太小、看不清落点，满级炮塔打出来的和一级一模一样，没有成长感。

**改动**

| 等级 | 贴图槽位 | 说明 |
| --- | --- | --- |
| Lv.1 | `fx_explosion` | 原来的「烟 + 火花」小爆炸 |
| Lv.2 / Lv.3 | `fx_explosion_l2` | 新素材，碎石 + 浓烟，更炸 |

- `Bullet` 新增 `src_level`，`configure()` 末尾多了 `lvl` 参数；`Tower._shoot()` 把 `level` 传进来。
- 判定只有一个：`src_level >= 2`，所以**三级炮塔天然沿用了二级的特效**，不需要再单独写分支。
- 尺寸公式（`Bullet._spawn_flash`）：

```gdscript
var sz: float = 2.0 + splash * 0.55 + (0.6 if is_crit else 0.0)
```

### 2. 变异「攻城巨炮」改成 9 帧序列特效

**动机**：攻城巨炮（`cannon_heavy`）是「一炮清空半条路」的重击，单张图放大淡出撑不住这个份量。

**改动**

- 新增通用 API `Fx.burst_seq(parent, pos, prefix, count, size, duration, fade)`：
  一张 billboard 方片，按时间逐帧换 `albedo_texture`，整体放大到 1.25 倍，末尾淡出。
  **帧图必须同尺寸同画布**，否则切帧时会抖。

```gdscript
	# 逐帧切贴图（并行分支 + 延迟），播完再淡出，避免"啪"地消失
	var step := duration / float(frames.size())
	var tw := mi.create_tween()
	tw.set_parallel(true)
	tw.tween_property(mi, "scale", Vector3(1.25, 1.25, 1.25), duration)
	for i in frames.size():
		tw.tween_callback(_set_tex.bind(mat, frames[i])).set_delay(step * float(i))
	tw.tween_property(mat, "albedo_color:a", 0.0, fade).set_delay(maxf(duration - fade, 0.0))
	tw.chain().tween_callback(mi.queue_free)
```

- `Bullet._spawn_flash()` 里判断 `src_mutation == "cannon_heavy"`，用序列帧代替单图：

```gdscript
		if src_mutation == "cannon_heavy":
			# 攻城巨炮是「一炮清场」的重击，爆炸再放大 1.9 倍才压得住
			if Fx.burst_seq(get_parent(), pos, "fx_siege", 9, sz * 1.9, 0.62):
				return
```

  `1.9` 是调了两轮的尺寸系数（1.1 → 1.5 → 1.9）。攻城巨炮 splash = 1.6 + 1.2 = 2.8，
  实际炸开宽度约 3.7 世界单位（接近 2 格），暴击约 4.3。想再大就继续抬这个系数，
  超过 2.5 会盖住路面、看不清怪物走位。
- `Bullet` 新增 `src_mutation`；`Tower._shoot()` 把 `mutation` 一起传进 `configure()`。

### 3. 变异「震地雷」：从「命中减速」改成「炸出泥潭」

**旧行为**：`mods = { "splash_add": 1.8, "slow_add": 0.16 }` —— 命中谁就给谁挂 16% 减速，
和冰塔的减速走同一个字段，谁强听谁的，控制感和「地面变泥沼」的设定完全脱节。

**新行为**：

- `TowerData.MUTATIONS` 的 `cannon_quake` 只保留 `splash_add: 1.8`，描述改成
  「溅射范围 +1.8，命中处炸出泥潭 / 踏入泥潭的敌人减速 16%（持续 1.5 秒）」。
- 命中点生成一个 `MudPit`（新脚本 `scripts/MudPit.gd`），区域内的敌人才被减速。

**新常量（`data/TowerData.gd`）**

```gdscript
const MUD_RADIUS := 1.7              # 泥潭半径（世界单位，1 格 = 2.0）
const MUD_TIME := 1.5                # 泥潭存在时间（秒），到点自行干涸
const MUD_SLOW := 0.16               # 泥潭内的减速比例
```

**`MudPit.gd` 实现要点**

| 点 | 做法 |
| --- | --- |
| 形状 | `QuadMesh` 绕 X 轴转 -90° 平铺地面（不是 billboard），宽 = 2×半径，深按贴图宽高比压缩 |
| 序列帧 | `fx_mud_0…6` 共 7 帧，**在 `life` 秒内正好走完一遍，不循环**（`step = life / 帧数`），最后一帧停住淡出 |
| 生命期 | 1.5s，最后 0.3s 把 `albedo_color.a` 淡到 0 再 `queue_free` |
| 减速扫描 | 每 0.1s 遍历 `enemies` 组，**只算水平距离**（x/z），半径内调用 `apply_extra_slow(0.16, 0.3)`；落地当帧额外扫一次 |
| 离开泥潭 | 施加时只给 0.3s，走出后自然恢复，不会一出圈就瞬间复原 |
| 缺图回退 | 整组 `fx_mud_*` 缺失时退化成一个半透明泥色圆盘（`CylinderMesh`） |
| 数量 | 炮塔攻速不高（震地雷 0.48/s 左右），同一时刻场上通常只有 1~2 个，未做上限 |

**踩过的坑（重要）**

泥潭第一版高度是用「命中点 − 0.7 + 0.05」反推的，结果**大部分时候看不见**。
`GameGrid.gd` 里地面是分层的：

```gdscript
const SURFACE_Y := 0.8        # 草地顶面（塔 / 敌人 / 路面都从这层起）
const ROAD_Y := 0.06          # 路面相对 SURFACE_Y → 路面顶面 0.86
const BRIDGE_CROWN := 0.08    # 桥上路面再拱到 0.94
```

敌人恒在 `SURFACE_Y = 0.8` 上走，反推出来的泥潭落在 `0.85`，**比路面低 1cm，被埋进地下**；
偶尔命中点在路肩 / 草地上时才露出来 —— 表现就是「有时候没生成」。

现在统一写死地形高度，不再从命中点反推：

```gdscript
	mud.setup(Vector3(pos.x, GameGrid.SURFACE_Y + 0.16, pos.z))
```

比普通路面高 0.10、比桥拱顶高 0.02，和路面流动箭头（`GameGrid.FLOW_Y = 0.14`）同一量级。
**以后往地面贴任何东西，都用 `GameGrid.SURFACE_Y + 偏移`，不要用敌人坐标反推。**

统一到 **128×96** 画布、**底部对齐 + 水平居中**（泥坑贴地，飞溅向上长），导出 `textures/fx_mud_0.png … fx_mud_6.png`。

### 4. 减速改成「两层乘区」（Enemy）

**动机**：泥潭的 16% 必须是**额外**减速。原来 `apply_slow()` 是「取更强」：

```gdscript
slow_factor = maxf(minf(slow_factor, 1.0 - factor), 0.25)
```

冰塔 -22% 在场时，泥潭的 -16% 直接被吞掉，等于白做。

**新结构**

| 字段 | 来源 | 叠加方式 |
| --- | --- | --- |
| `slow_factor` + `slow_timer` | 冰塔等塔类减速 | 同一层内**取最强**（不叠加），受首领 `slow_cap` 限制 |
| `slow_extra` + `_slow_extra_timer` | 泥潭这类**地形减速** | 与上面**乘算**，独立计时 |

速度计算两处（地面行走 + 飞行怪）都改成：

```gdscript
var step := base_speed * slow_factor * slow_extra * (1.0 + _haste) * delta
```

新增方法：

```gdscript
## 地形减速（震地雷的泥潭）：**乘算**叠在冰塔减速之上，互不覆盖。
## 例：冰塔 -22%（slow_factor 0.78）+ 泥潭 -16%（slow_extra 0.84）→ 实际 0.655 倍速。
## 走的是独立乘区，所以不会被 apply_slow 的「取更强」逻辑吞掉。
func apply_extra_slow(factor: float, time: float) -> void:
	if _dying:
		return
	var f := clampf(factor, 0.0, 0.9)
	slow_extra = minf(slow_extra, 1.0 - f)
	_slow_extra_timer = maxf(_slow_extra_timer, time)
```

数值对照：

| 场景 | 实际速度倍率 |
| --- | --- |
| 只有泥潭 -16% | 0.84 |
| 只有冰塔 -22% | 0.78 |
| 冰塔 -22% + 泥潭 -16% | 0.78 × 0.84 = 0.655 |

**要注意的联动**：`is_chilled()` 只看 `slow_timer`（冰塔那层），所以**踩泥潭的敌人不算「被冻住」**，
不会被喷火塔误判成冰冻目标去触发「融化」加成。以后再加别的控制效果，沿用这个原则：
新效果单独开乘区 / 单独判定，别塞进 `slow_factor`。

**多个泥潭重叠**：`minf` 取最强的一层，不会叠成 0.84 × 0.84。想让泥潭互相叠加就把这行改成乘法。

### 5. 火电「超载」爆炸特效升级

`Bullet._shock_blast()` 原来只有纯色光球 + 圆环，和放大后的炮塔爆炸明显不在一个量级。

### 7. 改完怎么自测

1. 起一局，建一座炮塔升到 Lv.2：命中爆炸应该是新图（碎石 + 浓烟）；Lv.1 仍是旧图。
2. 满级后选「攻城巨炮」：命中要放 9 帧序列，炸开约 2 格宽，`0.62s` 播完。
3. 满级后选「震地雷」：命中点必须**稳定**出现泥潭（重点看路面正中，别再被埋），
   1.5 秒内 7 帧走完一遍再淡出。
4. 同一只怪先被冰塔减速、再踩泥潭：速度应为「两个减速相乘」，肉眼比只有冰塔时更慢。
5. 踩泥潭的敌人被喷火塔打：**不应**出现白蓝色的「融化」蒸汽特效（泥潭 ≠ 冻住）。
