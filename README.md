# 终焉水晶 · Last Crystal —— 左侧水晶 · 固定路线 · 2.5D 塔防

计算机图形学与游戏开发 课程期末作业工程（Godot 4.7，GDScript）。

**玩法一句话**：守住地图**最左侧**的蓝色水晶，敌人从**右侧两个入口**沿棕色土路分头压上（两条路各自绕一段，在地图左中侧**汇成一路**撞向水晶，路面上有朝水晶滚动的箭头），路径格不能建塔；在路两侧的布防台上布阵，花金币把塔升级到 Lv.3、再从三条变异里选一个定型。

把几种塔防变体捏在一起：

| 变体 | 在本作中的体现 |
| --- | --- |
| **固定路线防守** | 敌人沿两条预设折线推进、中途汇流，路径格与河面不可建造，塔只能摆在布防台上 |
| **双入口** | 右上 / 右下两个入口交替出怪，火力必须分两摊，汇流点又得留够 |
| **升级成长** | 每座塔花金币升到 Lv.3（造价随等级上涨），等级越高伤害/射速/射程同步提升 |
| **变异 Mutation** | 满级后从 3 个方向里三选一，永久决定这座塔的最终形态 |
| **元素联动** | 冰塔减速后喷火加伤、闪电感电后喷火引爆，两条反应线各有专属强化卡 |
| **2.5D** | 3D 场景 + 固定俯视透视相机，逻辑仍是 2D 网格 |
| **Roguelike** | 每波结束三选一强化卡（26 张），效果永久叠加 |
| **零外部音频** | 10 种音效全部由 `Sound.gd` 在运行时合成 |

## 世界观 · 终焉水晶

**一句话**：世界已经被「蚀潮」吞没，只剩裂谷最西端一枚还在跳动的结晶。你是最后一位守望者，要守住它到黎明。

### 三层设定

- **晶冠大陆**：曾以七座「晶塔」为锚点维系的陆地。晶塔接连熄灭后，大地被一种叫「蚀」的活体潮水吞没，潮中的物理法则会失效。
- **裂谷（战场）**：大陆唯一尚未被完全淹没的狭长地带，东西走向，两侧是崩塌的蚀壁。谷底横着一条**断流的河**与两座旧桥，地表还留着两条**古道**——它们从东侧的两个裂口涌进来，绕过河与岩壁，最后在西侧的守誓台前汇成一条。
- **终焉水晶**：最后一枚尚未熄灭的晶核，坐在裂谷最西端的「守誓台」上。它一旦熄灭，世界进入永夜。

### 为什么是「固定路线」

蚀潮不是军队，它没有战术，只会顺着阻力最小的地势涌动。裂谷两侧是塌陷的岩壁，潮水被挤进那两条古道，只能沿着固定的沟壑反复冲刷、最后挤进同一条窄道。守望者改变不了它来的方向，只能决定**在哪一段路、用几座塔拦住它**——这也是为什么「两个入口」比「一个入口」更难：火力必须分成两摊，汇流点又必须留够。

### 机制 → 设定对应

| 机制 | 设定解释 |
| --- | --- |
| 左侧水晶 / 20 点生命 | 水晶的「焰心」，每漏过一只蚀者就被啃掉一格 |
| 两个入口 | 东侧蚀壁上被冲开的两道裂口，潮水从两处同时涌进裂谷 |
| 路径格不可建塔 | 古道被蚀浸透、地基不稳，只有路两侧的岩台能立塔 |
| 河流与木桥 | 谷底断流的残河；两条古道各由一座旧桥跨过去。桥面只能过人，不能立塔 |
| 河道不设塔位 | 水边地基最软，河岸一格以内都不给岩台（`GameGrid.SLOT_WATER_GAP`） |
| 塔 | 用晶屑铸成的「哨塔」，靠晶核驱动 |
| **金币升级** | 晶核会吸收「晶屑」自行成长（Lv.1→3），越往上吸收的量越多 |
| **变异（三选一）** | 晶核升至满阶后「定型」——三条互斥的共鸣路线只能选一条，选定不可更改 |
| 金币 | 「晶屑」——蚀者崩解后凝出的结晶，裂谷里唯一的硬通货 |
| 目标优先级（Q） | 守望者的「观星术」：混战中决定先压制最靠前的、最硬的，还是最近的 |
| 强化卡 | 前代守望者留在战场上的「遗物 / 残响」，每波涨潮退去后浮现一件 |
| 10 波 | 蚀潮的十次涨落；第 5 波**小首领**、第 10 波**大首领**亲自上岸 |
| 无尽模式 | 潮水不会真正退去，只是暂时平静——「余潮」 |

### 三幕结构

- **第一幕 · 序潮（1–2 波）**：蚀民试探。守望者熟悉「布阵」与「升级」，学会哪些岩台值得先占。
- **第二幕 · 涨潮（3–7 波）**：裂足、壳卫、幕行者陆续出现；第 5 波潮主登岸，第一次逼玩家做取舍——补伤害，还是补控制。
- **第三幕 · 终潮（8–10 波）**：蚀潮不再停歇，第 10 波终焉之影出现。守住，就是黎明。
- **尾声 · 余潮（无尽）**：天亮之后，潮水没有退去，只是安静下来。

### 结局

- **黎明（通关）**：水晶仍在呼吸，东方的蚀壁第一次裂开一道光。
- **永夜（失败）**：焰心熄灭，古道被潮水抹平，只剩风声。
- **余潮（无尽）**：守望者留在守誓台上，等下一次涨潮。

## 运行方式

1. 用 Godot 4.7 打开本目录（选 `project.godot`），项目根目录就是 `merge_maze_td/`。
2. 按 **F5**，主场景为 `res://scenes/Main.tscn`。命令行也可以直接跑：
   ```bash
   godot --path ./merge_maze_td res://scenes/Main.tscn
   ```

> 渲染后端 `gl_compatibility`，集显也能跑。UI 会自动加载系统中文黑体。
> 想在没有窗口的环境里做冒烟检查（CI / 批处理）：`godot --headless --path . --quit-after 150 res://scenes/Main.tscn`，
> 退出码 0 且没有 `ERROR / SCRIPT ERROR` 即启动正常。

## 地图规则

- 棋盘 **28 × 21** 格，格子边长 2.0（地图 56 × 42 世界单位）。**所有地图共用这个尺寸**（相机自适应、坐标换算、距离场都直接用这三个常量）。
- **最左侧、上下居中的 2×2 是基地**（蓝色水晶），敌人走到水晶面前就扣 1 点生命。水晶本身有浮空自转、蓝色 `OmniLight3D` 和一条自写 shader 血条（每帧手动朝向相机）。
- **两个入口都在右侧**（红色踏板 + 朝内箭头）：右上 `(27,3)`、右下 `(27,17)`。
- **路线是两条固定折线**（地图数据里的 `lanes` 拐点），不是单条。第一张图「裂谷」：
  - 北线：沿 `y=3` 向西 → 到 `x=22` 折下 → 沿 `y=7` 向西 → 到 `x=8` 折下 → 汇入主路；
  - 南线：沿 `y=17` 向西 → 到 `x=22` 折上 → 沿 `y=13` 向西 → 到 `x=8` 折上 → 汇入主路；
  - 两条线各 **33 格**，在 `(8,10)` 汇流后走 `(2,10)` 撞向水晶，去重后全图共 **59 个路径格**。
- 地面上的**棕色土路**就是这两条路线，路面上还有一串**朝水晶方向滚动**的暖白箭头（每条路线一份，数量按长度分配）。这串箭头**只在准备阶段显示**（`Main._refresh_flow_hint()` 每帧按 `wave_active` 同步 `GameGrid.set_flow_visible()`），开波后隐藏——敌人自己会走，箭头留着只会挡视线。出怪时两个入口**交替**，并有 25% 概率连发同一侧，制造偶尔「一边倒冲锋」的节奏。
- **路面是带状网格而不是贴片**（`_build_roads()`）：沿折线用 `SurfaceTool` 生成，拐角用 miter 斜切；路面宽 **3.2**（`ROAD_HALF` 1.6），下面再垫一层 3.9 宽的路肩（深色湿土），看起来像镶在草地里。
  路面上再压两层细节：中间两道 **0.4 宽的车辙**（`RUT_LAT` 0.62，压暗一档，抬高 0.008）和两侧 **0.32 宽的浅色毛边**（`ROAD_EDGE_LAT`，抬高 0.004）。它们和路面共用 `_add_polyline_ribbon` 的 miter 法向做横向偏移（`lat` 参数），所以拐角处窄条始终与路沿平行，过桥时也跟着桥拱一起抬起来。
- **河与木桥**：`_make_water_cells()` 逐行生成一条 2 格宽、左右摆动的河（裂谷共 **42 格**）；河心线经 Catmull-Rom 加密后生成带状水面（自写 unshaded 涟漪 shader），河岸比河面宽 0.45 露出一圈浅沙。路线与河相交处**自动架桥**（桥面 + 护栏横梁 + 立柱），裂谷 **2 座**。
  地图数据里 `river.enabled = false` 的图**不建水面节点**，改由地形表里的 `I` 字符逐格铺冻湖（霜渊），见下面的「多地图」小节。
- **地形装饰**：地图数据里的字符表驱动（`R` 岩壁 / `T` 树丛），裂谷共 **104 格**，左上岩壁、左下与右上树丛构成天然边界；装饰格同样不可建塔。
- **只有「布防台」能建塔（裂谷 19 个 / 霜渊 25 个）**：生成规则是「以路格为中心的**菱形距离恰好 2 格**（4.0 世界单位）」，并且八邻域内没有任何路格、离水面 1 格以内不生成、排除装饰 / 外圈 / 基地；最后用 `(x + y) % SLOT_MOD` 稀疏采样（`SLOT_MOD = 3`，2 更密 / 4 更稀）。占位道具所在的格子也会被排除。
  这样塔与路面之间**永远隔一条草地**，同时最脆的喷火塔（射程 5.6）仍能覆盖路面。地面显示成**石砌矮台 + 木板台面 + 台脚一线青色光边**（`_build_slot_markers()`，石台 / 4 条木板 / 光边各合一个 MultiMesh，21 个台子共 3 个 draw call；石台与木板都开 `use_colors` 做逐块明暗抖动）。
  **雪地图换一套皮**（`ground = "snow"`，见 `_build_snow_slots()`）：白色雪圆台 + 最外圈一道冷色淡影 + 青色台脚光边（同样 3 个 draw call，逐块明暗抖动）—— 灰石台和暖褐木板在整张白蓝的霜渊里是唯一的灰 / 暖色块，太跳；雪台只靠明度差和青边区分，台面顶 ≈ 0.866，塔建上去照样陷进雪里一点。
- 高度基准：瓦片从 `GameGrid.GROUND_Y = 0.4` 往上长（tile.glb 高 0.2 × 缩放 2），草地顶面 `SURFACE_Y = 0.8`；路肩 0.84 / 路面 0.86 / 河面 0.83 / 桥面 0.84、拱顶 0.92 / 布防台面 0.856，塔、敌人、特效全部踩在 0.8 上 —— 用错基准它们就会整层陷进地里。
- 建塔 / 升级 / 出售都**不会改变敌人路线**，塔的火力覆盖是唯一变量。

### 多地图（从第二张图开始）

地图不再写死在 `GameGrid` 里，而是全部塞进 `scripts/MapDefs.gd` 的 `MAPS` 表：一张图只需要一条数据（名字 / 地形表 / 路线拐点 / 河道 / 占位道具 / 天色 / 提示语），几何与渲染仍由 `GameGrid` 的通用代码完成 —— **新增地图不用写新脚本、不用新建场景**。

| id | 名称 | 状态 |
| --- | --- | --- |
| `rift` | 裂谷 · 守誓台 | 主线第 1 张，有河与两座木桥 |
| `frost` | 霜渊 · 永冻湖 | 第 10 波守住后可前往；冰洞窟，中央冻湖（`I` 地形表逐格铺，自写裂纹 shader），雪地 / 冻岩 / 白冰晶 / 冰刺全部程序化。专属怪：**碎冰者**（凿冰横穿冻湖）/ **霜语者**（套冰甲）/ **霜崽**（跟着冰洞游过去的小怪）；布防台是**白色雪台** |

- 切图流程：`MapDefs.pending_id`（static）→ `get_tree().change_scene_to_file(MapDefs.MAIN_SCENE)` → `Main._ready()` 里 `resolve_id()` 读走并清空。`change_scene_to_file()` 不能传参，所以只能走这条静态变量。
- 「打完第 10 波能前往」= 结算时 `MapDefs.next_id()` 按 `order` 顺延，有下一张才在结算面板上出「前往『霜渊』」按钮；金币与生命通过 `GameState.carry_gold / carry_lives` 继承（塔与卡牌不继承）。
- 开发时随时切图：右上角「地图切换 F1」或命令行 `godot --path . -- --map=frost`。
- 每张图还能单独换皮（都在 `MAPS` 那一条里，改不到任何脚本）：
  - `ground: "snow"`：草地瓦片换成雪面（世界坐标噪声 shader，格子之间无缝）；`corner_tree: false` 让四角长岩石而不是树；
  - `palette`：`rock` / `road` / `road_edge` / `road_rut` / `road_shoulder` / `road_glow`，把灰岩石压成冻岩、土路换成雪径；
  - `river.enabled = false` + 地形表里的 `I`：冻湖按格子铺（比河那条等宽带子灵活，可以挖湖湾）；
  - `props`：`crystal` 冰晶群、`spike` 冰刺、`obelisk` 方尖碑、`pad` 待建平台。
- 加第三张图：在 `MAPS` 里加一条、`order` 往后排即可（地形表 21 行 × 28 列，`lanes` 拐点横平竖直、末尾汇到 `(2,10)`）。

## 美术素材（3D 模型 + 贴图）

美术分三层，都支持「丢了就生效、删了就回退」：

- **塔（21 个程序化 GLB + 变异专属外观）**：`res://models/towers/tower_<kind>_l<1..3>.glb`，7 种塔 × 3 级。
  模型由 `tools/gen_tower_models.py` 用低多边形积木拼出来（同一套「底座 → 塔身 → 顶部武器」结构），
  **武器部件单独命名成 `Turret`**，所以瞄准时只有炮管绕自身 Y 轴转，塔身不动（`Tower._build_body`）。
  加载时按 AABB 归一化到 `TOWER_HEIGHT`（`_build_custom_tower`），换任何 GLB 都会自动贴地对齐；
  **变异**后脚下亮起变异色光环（自定义模型本身是多彩的，不做纯色染色，否则会把造型染平）。
  旧版的「Kenney 部件堆叠」代码（`_build_stacked_body` / `LVL_PARTS`）仍然保留作回退，
  但 21 个 GLB 齐全时走不到那条路。
- **变异专属外观**：命名成 `tower_<kind>_l<等级>_<变异短名>.glb`，由 `Tower._custom_model_path()`
  优先加载、找不到就回退普通模型（删文件即刻回到旧造型）。目前只有「双管齐射」做了模型：
  `tower_cannon_l3_twin.glb` —— 两根细炮管嵌在同一个炮座 + 中间轴套 + 后座里（**一体的双管**，
  不是两根各自摇摆的独立零件），后面还挂了一个弹药箱；`Turret` 节点整体转向，两管始终同向。
- **敌人（10 个程序化 GLB）**：`res://models/enemies/enemy_<kind>.glb`（grunt / runner / tank / shield /
  healer / splitter / miniboss / boss / icebreaker / frostweaver）。体型统一由 `EnemyData.DATA` 的 `size` 控制
  （小兵 1.45 → 重甲 1.95 → 小首领 2.35 → 大首领 3.05，大首领身宽约等于整条路面），
  加载后自动按身高缩放、底部贴地、水平居中；血条与头顶标记是程序化几何 + 自写 shader，
  血量、缓动、朝向相机都在 `Enemy.gd` 里手写，不走 3D 文字。
  **隐身怪**没有外部模型，走程序化半透明 + 隐身/显形循环，所以图鉴里它显示的是半透明方块。
- **霜崽 / 雪人王 / 霜松用程序化 3D 造型**：`scripts/FrostlingModel.gd` / `scripts/SnowkingModel.gd` / `scripts/PineBossModel.gd`，
  用基础几何拼出来（冰晶角 / 冰爪 / 王冠 / 冰甲 / 冰核……），造型刻意和原画做得不一样。
  原画 png 只作设计参考；billboard 精灵方案仍保留在 `Enemy._build_sprite_body()`（目前没有敌人使用），
  想临时贴一张原画就能换皮。注意它用的是 `ALPHA_SCISSOR` 而不是 `ALPHA` ——
  半透明材质不写深度，沉到冰面下的身体会从冰里透出来。
- **地面 / 水晶 / 岩石 / 树丛**：Kenney Tower Defense Kit 的 GLB（CC0 免署名，`res://models/kenney/`
  与 `models/tile*.glb`）。28×21 = 588 格地面按「瓦片种类 → MultiMesh」合批，整张地图只有几个 draw call；
  草地另有 per-instance 顶点色抖动，远看是一块块草皮而不是一整片纯色。
- **贴图热插拔**：敌人 / 子弹 / 天空等槽位把图片丢进 `res://textures/` 就会自动套上，
  没放图的槽位回退到纯色外观。

完整槽位清单、尺寸建议与素材来源见 **[`textures/README.md`](textures/README.md)**。
丢完素材记得**切回 Godot 编辑器**（或命令行 `--import`）让它导入一次；
重新生成塔 / 敌人模型则直接跑 `python tools/gen_tower_models.py` / `gen_enemy_models.py`；
霜崽 / 雪人王的原画处理脚本（`gen_frostling_sprite.py` / `gen_snowking_sprite.py`）保留着，目前只用来生成设计参考图。

## 音效与特效

- **音效全部是代码合成的**（`scripts/Sound.gd`，autoload `Sound`），项目里没有一个音频文件：
  `_ready()` 用 GDScript 逐样本算波形再 `encode_s16` 成 `AudioStreamWAV`，共 10 种
  `shoot / hit / explosion / place / sell / wave / leak / levelup / click / death`（22.05 kHz 单声道）。
  调用方式 `Sound.play("shoot")`；播放器池上限 **12**，满了就抢占「播得最靠后」的那个，
  避免密集开火时无限 new 节点。
- **调用点**：塔开火 / 命中 / 爆炸（`Tower`、`Bullet`）、建造 / 出售 / 升级 / 变异（`Main`）、
  开波 / 漏怪 / 死亡 / 首领技能（`Main`、`Enemy`）、UI 点击（`GameUI`）。
  加音效只需在 `Sound._ready()` 的字典里加一行，再在任意处 `Sound.play("名字")`。
- **特效库 `scripts/Fx.gd`**：`flash`（膨胀淡出光球）、`ring`（地面冲击环）、`blink`、`damage_number`（3D 伤害飘字）。
  飘字有全局上限 **14** 个，超出直接丢弃 —— 喷火塔这种高频伤害每发都飘字会把屏幕糊满，也会拖慢帧率。

## 关卡与数值（方便调参）

- 初始 **金币 300 / 生命 20**，共 **10 波**。
- **每波构成**（`Waves.plan()`，n = 波次）：小兵 `6 + 2n` 只恒定出现；第 3 波起加疾行者 `2n`、
  护盾怪 `n-1`、治疗怪 `n-2`；第 4 波起加分裂怪 `n-3`；第 5 波起加重甲 `n-3`、隐身怪 `n-4`；
  首领波额外补 2~8 只重甲开路。飞行怪已停用（循环注释掉，数据保留）。
  冰原图（`MapDefs` 里 `icebreaker: true`）另有碎冰者 / 霜语者 / 霜崽三只，规则见下面「冰原专属的三只」。
- 击杀奖励：基础 `reward` × `Waves.reward_scale(wave)` = 全局系数 `REWARD_COEF` × 波次曲线。
  - `REWARD_COEF` 默认 **0.88** —— 「打怪掉多少钱」的主开关，改这一个数就能整体加减收入
    （0.75 时前中期偏紧，塔都不敢升级；0.88 比最早的 1.0 仍低 12%）。
  - 曲线**先涨后跌**：`REWARD_EARLY_STEP` 0.03（第 1~5 波每波 +3%），
    `REWARD_LATE_STEP` -0.025（第 6 波起每波 -2.5%）。
  - 实际系数：第 1 波 ×0.88 → 第 5 波 ×0.99（峰值）→ 第 10 波 ×0.88 → 第 15 波 ×0.77 → 第 20 波 ×0.66。
  **不要让奖励一路涨**：敌人数量本身也随波次线性增长，单价再涨就是平方级收入，
  而玩家的支出上限有限（塔位固定），后期金币会直接溢出、难度形同虚设。
- 波间收入：`gold_wave`（固定金币卡）+ 利息，利息部分单波封顶 `Main.INTEREST_CAP`（默认 **150**），
  避免「本金越大利息越多」的滚雪球。
- **首领节奏**：第 5 波压上 **小首领**（620 血 / 2.35 体型，带重甲护卫）；
  第 10 波（最终波）压轴 **大首领**（1900 血 / 3.05 体型 / 15% 护甲，另有 1 只小首领护卫）。
  无尽模式沿用同一规律：每 5 波小首领、每 10 波大首领；首领不吃随机精英词条，
  脚下有专属色环（小首领橙、大首领红）、头顶悬浮带旋转宝石的 `BOSS` / `MINI BOSS` 标记，
  血条也更宽。**首领都带专属技能**，见下一条。
  霜渊（frost）会把第 5 波的小首领换成 **霜松**（680 血 / 10% 护甲 / 松绿光环），
  第 10 波的护卫也换成霜松、压轴换成 **雪人王**；其他地图仍是通用「潮主 / 终焉之影」。
- **首领专属技能**：结算逻辑在 `Enemy._tick_boss_skill()` / `_warcry()` / `_pulse()` / `_on_half_hp()`，
  数值全在 `EnemyData` 顶部常量里（`WARCRY_* / SUMMON_* / BOSS_PULSE_* / BOSS_ENRAGE_*`），
  `SUMMON_HP_RATIO` 统一控制半血触发点（默认 0.5）。
  - **小首领「潮主」**：①**战吼** —— 每 8 秒给半径 7 内的小怪 +30% 移速（持续 3 秒），
    地面亮橙红色冲击环 + 低音提示，配合重甲护卫逼玩家先处理首领；
    ②**集结** —— 半血时召唤 2 只小兵（头顶飘「集结」）。
  - **霜松**（霜渊小首领）：①**战吼** 与潮主同一套（给周围小怪加速）；
    ②**扎根** —— 半血时抖落一圈雪，召唤 **2 只霜崽**（冰原主题，而不是通用小兵）。
  - **大首领「终焉之影」**：①**压制脉冲** —— 每 11 秒让半径 7.5 内**所有塔停火 1.5 秒**
    （塔脚下亮紫圈、塔不会被摧毁也不会降级，压制结束后立刻恢复射击；点选该塔时信息面板会提示剩余时间），
    紫色冲击环 + 爆炸音；②**狂暴** —— 半血时移速 +35%、护甲 15%→25%，塔身压向暗红并常亮，
    飘出「狂暴」并召唤 3 只小兵。
  - **减速抗性**：`slow_cap`（小首领 0.55 / 大首领 0.4），单次减速最多只能削到该比例，
    冰塔不能把首领冻成不动的靶子；图鉴里会显示「减速抗性」标签。
  - **援军来源**：`Enemy._summon_guards()` 复用「剩余路径」生成（和分裂怪同一套），
    血量 = 当前波成长 × `SUMMON_HP_COEF`（0.6），走原路线、给正常击杀奖励。
- **首领战前预警**：下一波是首领波时，底部「开始第 N 波」按钮会变红并直接显示
  「⚠ 首领波 · 小首领 / 大首领」，开战前就能调整阵型；按钮 tooltip 里是完整的敌人构成。
- **敌人血量成长（线性）**：`Waves.hp_scale(wave)` = `1 + HP_SCALE_STEP × (wave-1)`，
  `HP_SCALE_STEP` 默认 **0.75**。也就是每多一波，所有敌人（含首领、召唤物）血量 +75% 基础值：
  第 1 波 ×1.0 / 第 3 波 ×2.5 / 第 5 波 ×4.0 / 第 10 波 ×7.75，无尽模式继续按同一斜率往上加。
  注意是**线性**而不是指数 —— 玩家的塔位与升级都是线性投入，指数血量会让中期直接崩盘。
  想整体变难就调大这个系数（0.75 → 0.9 约等于每波再硬 20%）。
- **精英词条（非首领敌人）**：每只怪生成时按波次抽词条（`Enemy._roll_elites()`）——
  概率 `0.06 + 0.035 × (波次-1)`，封顶 **45%**（第 1 波 6%、第 12 波起 45%）；
  第 6 波起有 40% 概率一次挂 **2 条**（词条互不重复）。四条词条：
  `fast` 移速 **×1.35** / `regen` 每秒回 **3% 最大生命** /
  `armored` 护甲 **+0.25**（叠完封顶 0.6，`_apply_elites()` 里压的）/
  `giant` 生命 **×1.6**、体型 ×1.3、奖励 ×1.5。
  首领不吃随机词条（它们本身就是设计好的强度节点），所以后期「同一种小兵突然变得很难啃」多半是词条。
- 首领数值在 `EnemyData.DATA` 的 `Kind.MINI_BOSS` / `Kind.BOSS` 里调。
- **护盾怪（壳卫）**：`EnemyData.DATA[Kind.SHIELD]` —— 120 血 / 护甲 **0.3**（减伤 30%）/
  速度 1.8 / 奖励 20。第 3 波开始出现，数量 = 波次-1。
  护甲对全部伤害一视同仁地做**乘法**减伤，所以它不会让某个塔彻底失效，只是单纯拖时间。
  历史上把它从「减伤 50%」下调过一次 —— 半减伤叠上血量成长后，有效血量比同期的重甲还厚，
  中期会明显卡节奏；现在再配上更高的击杀奖励（20，重甲是 24 但血量翻倍），
  打掉它是有回报的。精英词条「坚甲」的护甲上限在 `Enemy._apply_elites()` 里压到 **0.6**，
  避免护盾怪再叠成「打不动」的怪。
- **冰原专属的三只**（只在 `MapDefs` 里 `icebreaker: true` 的图出现，目前只有霜渊）：
  - **碎冰者**（`Kind.ICEBREAKER`，320 血 / 1.25 速 / 15% 护甲 / 体型 2.0）：不走雪径 ——
    `GameGrid.swim_route_home()` 给它一条「雪径 → 横穿湖面 → 另一侧雪径」的路线（地图里画好的
    `swim_cross` 优先，没有才跑一次带权 A*；水面权重 0.85，让它在「过湖不比绕路远太多」时愿意下水）。
    走到水边砸开冰面、**整个人沉到冰面以下**，冰面上只留波纹圈 + 冰下暗影表示位置；水里速度 ×0.78，
    第 3 波起出现、每波最多 4 只。
  - **霜语者**（`Kind.FROSTWEAVER`，150 血）：周期给半径内的同伴套冰甲（按目标最大生命吸收伤害），
    火属性破甲快 2.6 倍；第 4 波起、每波最多 3 只。
  - **霜崽**（`Kind.FROSTLING`，52 血 / 2.9 速 / 体型 1.05，程序化 3D 造型）：**自己不会碎冰** ——
    冰面没通时沿雪径绕湖；碎冰者第一次下水会把 `GameState.ice_opened` 置 true，之后刷出的霜崽
    才跟着冰洞走水下段抄近路（正式波次和上帝模式刷怪走同一条规则）。第 2 波起出现、每波最多 8 只。
    `ice_opened` 在 `GameState.reset()` 里清掉，所以换图 / 重开都会回到「湖没通」的状态。
- **塔随波次解锁**：`TowerData.UNLOCK` 定义每种塔从第几波开始可建 —— 箭塔 / 炮塔第 1 波，
  冰塔第 3 波、喷火塔第 4 波、闪电塔第 5 波、狙击塔第 6 波、弹射塔第 7 波。
  未解锁的商店按钮会灰掉并显示「未解锁 第 N 波」；每波结束时新解锁的塔会在信息面板提示一次，
  波间休整即可提前建造。
- **飞行怪暂时停用**（无视地形直线飞到基地，强度过高）：`Waves.plan()` 里对应的生成循环已注释掉，
  数据与逻辑（`Kind.FLYER`、`flying` 分支）都保留，想恢复只需把那段循环取消注释。
- 路线与基地位置：`GameGrid._make_lanes()`（两条路线折线）/ `GameGrid._make_home_cells()`（最左侧 2×2 基地）。
- 塔数值全在 `TowerData.DATA`（`cost / dmg / rate / range / splash / slow / dot`）。
  当前基线（Lv.1 单发伤害）：箭塔 13 / 炮塔 29 / 冰塔 9 / 狙击塔 112 / 闪电塔 19 / 喷火塔 5（+灼烧 13/s）
  / 弹射塔 16；炮塔 `splash` 1.6（溅射半径）、冰塔 `slow` 0.22（减速比例）。
  冰塔虽然带 `"beam": true`（外观是持续射线），但**伤害仍是「单发 9 × 攻速 1.05/s」**，
  和改造前完全一致，只是省掉了子弹飞行那段（详见下方「冰塔：持续冰冻射线」）。
  这轮整体下调过约 10~20%（此前箭塔 15 / 炮塔 34 / 狙击塔 140 / 闪电塔 24 / 喷火 6+16 / 弹射 18），
  原因是升级 + 变异的乘算叠完后，塔的 DPS 明显盖过了线性成长的血量曲线。
- **射程与路宽**：路面半宽 `GameGrid.ROAD_HALF` = 1.6，布防台离路中心线 `SLOT_GAP` = 2 格（4.0 单位），
  所以塔对路面能覆盖的路段长度 = `sqrt(range² - 4²)`，而不是直接等于射程。
  路面加宽后各塔射程已按这个口径统一上调：箭塔 7.0 / 炮塔 6.2 / 冰塔 5.8 / 狙击塔 10.8 /
  闪电塔 6.6 / 喷火塔 5.6 / 弹射塔 6.2（路边约覆盖 4~6 单位路段）。
  继续改路宽或 `SLOT_GAP` 时要同步复核这几个数，短射程塔低于 5.2 就会出现「建了打不到」的死位。
- **溅射衰减**：爆炸不再对圈内所有人打满额伤害 —— 被**直接命中**的目标吃 100%，
  半径内的其他敌人只吃 `TowerData.SPLASH_DMG_COEF`（默认 **0.55**）。所以炮塔的定位是
  「单体重击 + 少量范围补刀」，而不是一炮清场；把该常量调回 `1.0` 即恢复旧手感，
  调得更低则进一步弱化群伤（减速等附带效果不受衰减影响，圈内全员照常挂上）。
- **冰塔：持续冰冻射线**（`TowerData.DATA[FROST]["beam"] = true`）：
  外观上锁定一个敌人一直照射不撒手，但**伤害节奏沿用原来的攻速** —— 每 `1/fire_rate` 秒
  打出一发满额 `damage`（暴击 ×2），飘字、溅射衰减、减速刷新都和子弹命中一模一样。
  也就是说：单发数值、射速、DPS、升级与变异的收益一个字都没改，变的只是
  「子弹飞过去那 0.3 秒」没有了 —— 锁上就打，射线一直连着。
  表现层是 `scripts/IceBeam.gd`（两条正对镜头的三角带 + 末端冰爆光斑，每帧重画，不加节点）；
  逻辑层是 `Tower._update_beam()` / `_beam_apply()`，`_beam_tick` 就等价于原来的 `cooldown`。
- **减速时长与强度**：冰塔射线的减速持续时间是 `TowerData.SLOW_TIME`（默认 **1.15s**），
  强度 = `DATA` 里的 `slow`（0.22）× `LV_SLOW_GROWTH`（0.12/级）× `GameState.buffs["slow"]`。
  这轮把强度和成长都压了一档（原来 0.26 / 0.20 每级）：Lv.3 冰塔的减速从约 36% 降到约 27%，
  避免一个冰塔就把整条路钉死。变异「霜环」不再走加值，而是用 `slow_set` 定死在 **50%**（见下条）。
  时长统一由 `SLOW_TIME` 控制（射线期间每跳都会刷新它，所以敌人在射线里一直是被冻住的）。
- **变异「霜环」= 光环塔**：数据里带 `"aura": true` + `{"dmg_mul": 0.0, "slow_set": 0.50}`。
  它**没有任何攻击方式**：不出射线、不生成子弹、也不触发毒 / 流血这类「弹药词条」，
  只把射程圈铺满冰雾（`scripts/FrostFog.gd`：三层圆盘 + `fx_frost_fog` 贴图，反向缓慢自转），
  圈内敌人每 `AURA_TICK`（0.2 秒）刷一次减速。雾圈半径就是 `range_v`，
  升级 / 变异 / 卡牌改了射程会重新铺一遍，所以雾圈和射程圈严丝合缝；
  被首领脉冲压制时冰雾熄灭，等于视觉上的「熄火」。加同类光环塔 = 新变异里写 `"aura": true`。
- **变异（满级三选一）**：塔升到 **Lv.3** 后，浮窗 / 信息面板里的「升级」按钮会变成
  「变异（N 金）」，价格 = 塔造价 × `TowerData.MUTATION_COST_COEF`（默认 0.6）。
  弹出的三选一面板**会暂停游戏**（`GameUI.show_mutations` → `get_tree().paused = true`），
  三个方向的说明可以慢慢读完再决定；选完立刻生效、**之后不能更改**，ESC 可随时关掉面板稍后再选。
  关闭 / 选定 / ESC 都会还原打开前的暂停状态（本来就在暂停就保持暂停，不会把玩家按的暂停一起解掉）。
  波次结算 / 卡牌 / 结算 / 跳波复位时都会先收起变异面板，避免两层遮罩叠在一起，也避免暂停状态泄漏。
  变异费也是后期主要的金币出口：满级塔全部变异一遍约等于再花掉 60% 的造塔预算。
  每条路线只改数值（乘/加在基础值之上），数据全在 `TowerData.MUTATIONS`
  （每塔 3 条，`mods` 支持 `dmg_mul / rate_mul / range_mul / dot_mul / splash_add / slow_add / slow_set / chain_add / crit_add`；
  顶层 `aura: true` 表示「变异后完全没有攻击方式」的光环塔，`tint` 决定塔身与光环颜色）。
  加一条路线 = 加一条数据，不用改逻辑。
  例外：**「震地雷」**不再用 `slow_add`，改成命中处生成泥潭（`scripts/MudPit.gd`），
  减速走 `Enemy.apply_extra_slow()` 的独立乘区，详细记录见 `docs/CHANGELOG.md`。
  本轮把全部 21 条变异整体调弱了约 15~25%（例：「攻城巨炮」伤害 +60% → +40%、攻速 -25% → -22%；
  「疾风弩」攻速 +75% → +45%；「雷暴 / 跳弹」链式 +3 → +2），
  目标是让变异成为「换一种打法」而不是「凭空多一倍的数值」。`desc` 里的百分比与 `mods` 必须同步改。
- **等级成长**：`TowerData.LV_DMG_GROWTH / LV_RATE_GROWTH / LV_RANGE_GROWTH / LV_SLOW_GROWTH`
  控制每升 1 级的增幅，当前为 **0.72 / 0.16 / 0.16 / 0.12**（伤害成长从 0.95 下调）。
  也就是 Lv.3 满级塔的伤害 = 基础 ×2.44（原本 ×2.90），射速 ×1.32，射程 ×1.32。
  升级仍然是「省塔位」的划算路线，但不再能靠一座满级塔单独顶住一路。
- **元素联动「冰火两重天」**：喷火塔命中**正被冰塔减速**的敌人时，直接伤害额外提高
  `TowerData.CHILL_DMG_BONUS`（默认 0.6 → ×1.6）。命中处会冒白蓝蒸汽、敌人身体泛白，
  塔的信息面板里也会写明这条联动；把该常量改成 `0.0` 即关闭。
- **元素联动「火电引爆」**：闪电塔命中会给目标挂 `TowerData.SHOCK_TIME`（2.5s）的感电，
  敌人身体泛紫；喷火塔命中感电目标时引爆一次小范围爆炸（半径 `SHOCK_BLAST_RADIUS` 2.2、
  伤害 = 本次喷火命中 × `SHOCK_BLAST_MULT` 1.4），爆炸后消耗感电，需要闪电塔重新打上标记。
  爆炸直接用 `take_damage` 结算，不会无限连锁。
- 卡池共 **26 张**，全在 `Cards.POOL`；新增一张卡 = 在 `data/CardData.gd` 加一条文案 + 在 `Cards.apply()` 里补一个 `match` 分支。
- **强化卡数值刻意压得小**：卡是**永久叠加**的，一张 +40% 拿两次就是 +80%，
  而敌人血量只是线性成长 —— 所以单张幅度控制在 10~30%（伤害卡 +12%、塔专属卡 +30%、
  狂暴之血 +24%/-10% 攻速、暴击 +7%、减速 +10%），强度靠「拿得多」而不是「一张很强」。
  改 `Cards.apply()` 里的数字时，**务必同步 `CardData` 的 `desc` 文案**。
- **元素反应强化卡**（把两种联动的伤害单独做成成长线）：
  - 「熔核共鸣」`melt`：融化反应（喷火打结霜）伤害 **+30%**，读 `GameState.buffs["melt_dmg"]`，
    在 `Bullet._synergy_multiplier()` 里与 `CHILL_DMG_BONUS` 相加。
  - 「过载增幅」`overload`：超载爆炸伤害 **+35%**，读 `buffs["overload_dmg"]`，
    在 `Bullet._shock_blast()` 里与 `SHOCK_BLAST_MULT` 相加。
  - 「元素共鸣」`reso`：上面两者各 **+15%**（一张卡两条反应线都吃）。
- **子弹附加状态卡**（拿卡后**所有塔**的子弹都生效，包括链式闪电的每一跳、溅射的每个目标）：
  - 「淬毒弹头」`poison`：中毒 **7 dps / 3s**，结算走 `Enemy._take_raw()`，**无视护甲**；
  - 「放血锋刃」`bleed`：流血 **8 dps / 2.5s**，走普通 `take_damage()`，**吃护甲减免**；
  - 两条状态和「燃烧」共用「每 0.5 秒结算一次」的节奏，持续时间取最大值（不叠层），
    强度则随拿卡次数线性相加；敌人身体会染色区分：中毒墨绿、流血暗红。
  - 实现位置：`Bullet._apply_effects()` 统一读 `GameState.buffs` 挂状态，
    `Enemy._process` 里结算；想加新状态（灼烧/易伤等）照这个套路加一组 `_xxx_dps/_timer/_tick` 即可。
- **命中类 / 触发类强化卡**（都是「让后续攻击更疼」或「额外触发一次」的思路）：
  - 「破甲弹头」`break`：命中后敌人护甲 **-26%**（3s）→ `Enemy._armor_break`，取最大值不叠层；
    护盾怪（护甲 30%）几乎被剥光，和中毒一起构成反重甲流派。
  - 「易伤标记」`vuln`：命中后敌人**受伤 +10%**（3s）→ `Enemy._vuln`，在 `take_damage()` 里乘算。
  - 破甲 / 易伤都是「这一发只负责挂标记，真正的收益在后面的命中」，所以同发子弹不会自我增益。
  - 「处决协议」`exec`：目标生命低于 `Bullet.EXECUTE_HP_RATIO`（35%）时伤害 **+35%**。
  - 「连锁爆破」`blast`：敌人死亡时对半径 `Enemy.DEATH_BLAST_RADIUS`（2.4）内的敌人
    造成**自身最大生命 12%** 的伤害（`Enemy._death_blast()`）；伤害随波次血量成长自动放大，
    每个敌人只在自己死亡时炸一次，不会无限连锁。
  - 「守夜人」`night`：每波结束回复 1 点生命（`Main._end_wave()`，上限 20）。
  - 「废料回收」`scrap`：出售返还 50% → **65%**（`Main._sell()`，`buffs["refund"]` 封顶 0.9，防止卖塔套利）。

### 想调难度

- 整体变难：调大 `Waves.HP_SCALE_STEP`（每波线性加血），或调大 `Waves.plan()` 里的数量。
- 变简单：调小系数，或把 `GameState.START_GOLD` 调大。
- 金币太多 / 太少：先调 `Waves.REWARD_COEF`（0.88，打怪收入的主开关），
  再考虑 `REWARD_LATE_STEP`（后期曲线）、`Main.INTEREST_CAP`（波间利息上限）
  与 `GameState.START_GOLD`（只影响开局，不动中后期）。
- 塔太强 / 太弱：`TowerData.DATA` 的 `dmg` 管 Lv.1 强度，`LV_DMG_GROWTH` 管满级增幅，
  两者一起调；控场强度看冰塔的 `slow` 与 `LV_SLOW_GROWTH`（顺手也要看 `TowerData.SLOW_TIME`）。
- 波数：改 `Waves.TOTAL`。
- 路线变长变绕：编辑 `GameGrid._make_lanes()` 里的两条折线即可（最后一段都要落进 `(2,10)` 附近再进基地）。
- 布防台太多 / 太少：改 `GameGrid.SLOT_MOD`（当前 3，约 21 个点；2 更密、4 更稀），
  或改 `SLOT_GAP` 调整塔与路面的距离（注意同步复核各塔射程）。

## 涉及到的图形学 / 游戏开发知识点（写报告可直接用）

1. **网格与坐标变换**：格子 ↔ 世界坐标互转（`cell_to_world` / `world_to_cell`）。
2. **多路线展开与汇流**：`lanes: Array[Array[Vector2i]]` 描述两条折线，`path_cells` 是它们**去重后的并集**（33+33 → 59 格）；生成敌人时把格子转成世界坐标路点数组（`path_world`），敌人按路点逐段推进并累计 `progress`（已行进距离），塔用它实现「打最靠前」的优先级。以基地为源点的 BFS 距离场 `_dist` 仍保留，作为「最近可达格」的兜底。
3. **静态路径约束 + 占位管理**：`blocked` 位图记录被塔占据的格子，`towers` 字典索引塔实例，`_path_set` 哈希表让「是否路径格」判定为 O(1)。
4. **建造校验（防呆设计）**：`can_place()` 按「越界 → 外圈 → 基地 → 路径格 → 已有塔 → 格内有敌人」逐条否决，保证固定路线不会被占用或堵死。
5. **实时光照与阴影**：主光 + 补光双 `DirectionalLight3D`、`Environment` 环境光、SSAO、Glow，基地另有 `OmniLight3D` 点光源。
6. **自定义 Shader（血条）**：敌人血条用 `shader_type spatial` 手写——`uniform ratio` 在片元阶段裁剪填充宽度，颜色随血量绿→红渐变。
7. **材质与着色模式**：`StandardMaterial3D` 的 unshaded / transparency / emission。
8. **Billboard 与节点缩放的坑**：`BaseMaterial3D` 的 billboard 在顶点着色器里用相机基向量替换模型旋转，会**丢掉节点缩放**（血条曾因此永远满格）；Godot 4 自定义着色器也没有 `billboard` 这个 render_mode（写了直接编译失败）。最终方案：血条在 GDScript 里手动把相机正交基拷给血条节点，画面依旧正对镜头。
9. **三条并存的美术管线**：① 程序化建模生成的 GLB（`tools/gen_tower_models.py` / `gen_enemy_models.py` 产出 21 个塔 + 8 个敌人，运行时 `load()` PackedScene 再 `instantiate()`，`ModelLib` 做缓存）；② Kenney Tower Defense Kit 的 GLB（地面瓦片、水晶、岩石，CC0）；③ 纯代码生成的程序化几何（子弹、血条、出生点箭头、特效）。三者可以逐槽位替换。
10. **调色板贴图（Texture Atlas）**：Kenney 模型的 160 个部件共享一张 `colormap.png`，每个模型的 UV 已映射到图上对应色块，因此整包只需要一张贴图。
11. **实例级换色**：`ModelLib.tint()` 用 `material_override + duplicate()` 给单个实例染色，不会污染共享材质。注意它对**自带上色的程序化 GLB 是禁用的**（会把整套造型染成纯色），所以变异塔只加脚下光环、不改塔身颜色。
12. **AABB 归一化与可动部件**：外部 GLB 加载后读 AABB 求出当前高度、按 `TOWER_HEIGHT` 等比缩放、再用 `box.position.y` 把底部贴到地面 —— 换任意模型都能自动对齐全。塔的武器部件单独命名 `Turret`，运行时 `find_child("Turret")` 拿到节点只转它，实现「炮塔转向而塔身不动」。
13. **折线带状网格与 miter 拐角**：路面 / 河面都由 `SurfaceTool` 沿折线生成 —— 每个点算一条横截面法向，转角处取前后法向之和再除以投影（miter），相邻横截面连成四边形；三角形必须按 Godot 的**顺时针**正面绕序输出（`p0 → p3 → p2 → p1`），否则整片地被背面剔除、看起来像「消失了」。
14. **Catmull-Rom 平滑**：河道由逐行格心组成的「楼梯折线」，用 Catmull-Rom 加密后才变成自然曲线，再交给同一条 ribbon 函数生成水面。
15. **多实例渲染 / 批处理**：地面数百块 Kenney 瓦片、布防台地砖与圆环、路面上滚动的方向箭头都用 **MultiMeshInstance3D** 按「材质/形状 → MultiMesh」合并，588 格地面只要几个 draw call；`visible_instance_count` 控制箭头实际数量，顶点色做 per-instance 明暗抖动。
16. **摄像机投影与拾取**：固定角度透视相机；用 `project_ray_origin/normal` 生成屏幕射线，与地面 `Plane` 求交实现「鼠标选中格子」。塔顶浮窗则是反向操作：`unproject_position` 把 3D 塔坐标投影回屏幕，再夹到视口内。
17. **对象管理与性能**：塔/敌人/子弹运行时实例化并 `queue_free` 回收；路线是静态的，建塔不会重建路径，只在网格变动时刷新占位。
18. **Roguelike 系统设计**：卡池抽卡、唯一卡去重、buff 乘法叠加（`GameState.buffs`）。
19. **游戏循环与状态机**：建造 / 战斗 / 波次结算 / 选卡 / 变异五个阶段；`Main` 是 `PROCESS_MODE_ALWAYS`（暂停时仍可移动相机），战斗子树显式设为 `PAUSABLE`，所以暂停只冻结战场、不冻结 UI。
20. **暂停语义的「记录—还原」**：图鉴与变异面板都会临时暂停游戏，打开前记下 `get_tree().paused`、关闭时只恢复「自己暂停的那一次」，避免把玩家手动按的暂停一起解掉，也避免重复打开时把暂停状态记错。
21. **程序化音频合成**：`Sound.gd` 不加载任何音频文件，而是按采样率逐点算波形（正弦 + 噪声 + 包络），`encode_s16` 成 `AudioStreamWAV`；配一个 12 路播放器池避免高频音效爆节点。
22. **运行时资源热插拔**：`TextureLib` 扫描 `res://textures/` 建索引、缺图回退；`ModelLib` 按 GLB 文件名加载并缓存 PackedScene，实现「改美术不用改代码」。
